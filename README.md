# FractureTAU — dynamic-fracture

Machine-learning prediction of the spatiotemporal evolution of fracture in
microstructures. A PyTorch model (**FractureTAU**, a SimVP encoder/decoder + TAU
translator, written from scratch for this project) is compared head-to-head
against the ConvLSTM reference of K. Martinus, *Fracture Prediction Using Machine
Learning for Brittle Materials Under Compression* (M.S. thesis, Purdue
University, 2026), under an **identical autoregressive (AR) rollout protocol** on
the same simulation dataset. The baseline is run **inference-only** from its
published frozen `.keras` weights, which are SHA256-checked before and after every
evaluation job so they cannot drift.

At inference FractureTAU reproduces a full simulation in **3.806–4.419 s** on an
A100-80GB, against **30–66 h** for the FEM simulation it surrogates (rollout loop
only; different frameworks and hardware, so this is a regime comparison, not a
controlled benchmark).

> **Core result:** FractureTAU **0.8621** vs ConvLSTM **0.5767** late-rollout
> macro-F1 (mean over seeds 42/43/44 across all 16 canonical held-out cases;
> Δ = +0.2854, one-sided Wilcoxon W = 136.0, p = 1.526e-5, n = 16, **higher on
> 16 of 16 cases**). On 9 further out-of-distribution simulations spanning 5
> microstructure families held out of training, FractureTAU is higher on **9 of
> 9**. See *Reproducibility honesty* below for how to read these numbers.

Full comparison table (all 16 cases + the significance line):
[`results/comparisons/tau_headline_vs_base_regen.md`](results/comparisons/tau_headline_vs_base_regen.md).
Per-case seed spread and the physical metrics:
[`results/phys_metrics/PHYS_REPORT.md`](results/phys_metrics/PHYS_REPORT.md).

**Where the data is not.** The raw per-timestep simulation CSVs are proprietary to
the data owner and are **not redistributed here**. `ALL_INPUTS/DATASET/` is an
empty placeholder in this public tree; the code resolves it to Purdue Gilbreth
cluster storage at run time. Everything derived from it (the memory-mapped `.npy`
grid caches, the FractureTAU checkpoints, and the per-run `OUTPUTS/` trees) also
lives on the cluster and is regenerated by the committed scripts once the dataset
is mounted.

## Two-codebase layout

This repo holds **two separate pipelines** that must never cross-import — the
shared CSV dataset is the only seam between them:

| | `new_model/` | `kathleens-model/` |
|---|---|---|
| Framework | **PyTorch** (Python 3.11) | **TensorFlow/Keras** (Python 3.12) |
| Model | FractureTAU (SimVP + TAU) | ConvLSTM (frozen reference) |
| Source | `src/` package | `source/` flat modules |
| Entry points | `python -m src.train` / `python -m src.evaluate` | `python train.py --mode N` / `python evaluate.py` |

The TensorFlow reference checkpoints are SHA256-verified and **never modified** —
they are the frozen, honest baseline.

Shared, framework-free glue (e.g. `case_registry.py`, the dashboard +
`results/phys_metrics/` analysis modules) is stdlib/numpy only so it imports under
either environment.

## Reproducible evaluation

The analysis/eval environment is **version-pinned** via `uv.lock` (PAPER-03).

```bash
cd dynamic-fracture
uv sync --group dev            # recreate the pinned env from uv.lock (incl. dev/test deps)
```

Regenerate the **headline comparison + physical metrics** report in **one
command** (PAPER-04):

```bash
bash scripts/repro_eval.sh                  # full regen for run 'tau_refined'
bash scripts/repro_eval.sh --run-name foo   # a different run
bash scripts/repro_eval.sh --skip-eval      # reuse existing eval outputs, rebuild reports only
bash scripts/repro_eval.sh --smoke          # dry-run the wiring (no GPU/artifacts) — used by CI
```

`scripts/repro_eval.sh` chains the three first-party drivers behind one entry
point:

1. `new_model/` → `python -m src.evaluate` — per-case AR (and optional
   `--teacher-forced`) rollout.
2. `results/dashboard/make_report.py` — the locked-order multi-metric dashboard
   (`results/REPORT.md` + figures).
3. `results/phys_metrics/make_phys_report.py` — the PHYS-01..06 physical-metrics
   report.

It runs end-to-end only on a machine that has the pulled run artifacts /
checkpoints; `--smoke` validates the wiring everywhere else.

### Cluster runs

Training and full evaluation run on the Slurm cluster via the existing batch
scripts — use these, do not duplicate them:

- `new_model/scripts/*.sbatch` — FractureTAU train / sweep / evaluate / seeds /
  ablation jobs.
- `kathleens-model/scripts/*.sbatch` — ConvLSTM reproduction + reference-baseline
  jobs (activate the TF env via `scripts/tf_env.sh` first).

## Reproducibility honesty

- **Results are reported as mean ± std over 3 seeds (42 / 43 / 44)**, with a
  one-sided Wilcoxon significance test over the BASE cases. Every headline number
  is recorded next to its checkpoint hash — the three frozen headline checkpoints
  are `headline_s42` `0f55814f…`, `headline_s43` `6a09694a…`, `headline_s44`
  `f97f429e…`, and each is re-hashed into every generated comparison file.
- **The comparison is asymmetric, and we say so.** FractureTAU is a three-seed
  mean; the ConvLSTM is a *single frozen published checkpoint* run inference-only.
  An attempted from-scratch reproduction of the baseline recovered most of the
  autoregressive collapse but could not be matched to the published numbers
  exactly, because the original training partition was not recoverable — so we use
  the published frozen weights, which evaluates the baseline as its author
  released it.
- **Per-case seed variance is occasionally large.** Most cases sit below 0.03
  three-seed std, but `test_MS5_V150ms_inc` reaches 0.32. Read per-case numbers
  with their spread; do not quote a single seed.
- **Rollout length varies by case** (183–363 steps across the 16 canonical
  cases). The reported metric is macro F1 over the last 20% of each case's own
  rollout.
- **The SED extension is a negative result and is reported as one.** Switching the
  target from binary crack mask to strain-energy-density regression produced no
  genuine skill in *either* model (rel-L2 < 0.8 on only 0–2 of 16 cases in every
  configuration tested). FractureTAU-SED has a ~38% lower mean rel-L2 than
  ConvLSTM-SED but wins **zero** additional cases — an error-magnitude
  improvement with no case-level separation. It is **not** a regression twin of
  the fracture win and must not be cited as one.
- The environment is **version-pinned via `uv.lock`**. We **do NOT claim
  bit-determinism**: GPU non-determinism, cuDNN kernel selection, and AMP make
  exact bit-for-bit reproduction unrealistic and unnecessary (Pitfall 9).
  Reproducibility means *the same pipeline + pinned env + fixed split + seeds
  reproduces the result within reported variance*, not identical bits.
- A frozen v1.0 result archive (comparison tables, diagnostics, SHA256 manifest)
  is kept under [`archive/v1.0/`](archive/v1.0/MANIFEST.md).
